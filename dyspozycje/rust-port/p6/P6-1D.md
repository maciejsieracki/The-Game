## 5. Zalozenia i zachowania weba odtworzone 1:1 (luki rozstrzygniete ZALOZENIEM)

1. **`ł`/`Ł` nie dekomponuje sie w NFD** i zostaje `ł` po `stripDiacritics`; stad jednostka o nazwie `Łucznik` z rola `Wręcz` ma kategorie `piechota` (nazwa `łucznik` nie zawiera tokenu `lucz`), a `Łuk długi` tez `piechota`. To zachowanie weba, odtworzone i potwierdzone wektorem (jednostki syntetyczne 0 i 22). Zalozenie: NIE poprawiamy go w porcie (parytet), nalezy zglosic jako ewentualny blad weba osobnym tematem.
2. **`civMatrixParam`** (civ-matrix.ts) jest odtworzony tylko jako prywatna funkcja `matrix_param` w `civ_bonuses.rs` (wiersz po `ikonaId`/`typCywilizacji`/`Cywilizacja` bez wzgledu na wielkosc liter, potem `defaults`, potem 0). Pelny port `civ-matrix.ts` nalezy do osobnego tematu P6.1 (rownolegle P6.1B/C); funkcje przyjmuja `&CivMatrixFile` jawnie zamiast globalu.
3. Wejscia opcjonalne weba (`bonusy` `undefined`) -> pusty slice; brak pola kontekstu -> `false`/pusty tekst; `usedNames` opcjonalne -> `Option<&HashSet<String>>` (rozroznienie `None` (= niejawny prefiks kolejki) od pustego zbioru zachowane i przetestowane).
4. Indeksy i numery rywali: `i64` (domena calkowita, jak w uzyciu weba).
5. `stripDiacritics`: tabela obejmuje cala BMP od U+00C0 (bez surogatow i sylab Hangul U+AC00-U+D7A3). Plaszczyzny astralne i Hangul: **NIE_ZMIERZONO**, poza domena danych gry (dane to polskie nazwy). Test Rust porownuje wynik z Node dla KAZDEGO znaku BMP (hash `bmpHash`), pomijajac Hangul oraz U+A7CE, U+A7D2, U+A7D4: te trzy litery znane sa nowszej wersji Unicode w Rust 1.97 niz w ICU Node 22.22 (dryf wersji `toLowerCase`, nieistotny dla danych gry) - jawny wyjatek.
6. `validateCityNamesPools`: przypadek webowy `miasta_cywilizacji == undefined` jest **NIE-DOTYCZY** w Rust (typ `CityPool` wymaga pola, `deny_unknown_fields`), wiec wektor go nie zawiera.
7. `suggestPlayerFoundCityName` ma nieuzywany argument `playerOwnerId`, a `pickAiFoundCityName` nieuzywany `ikonaId` - zachowane w sygnaturach (`_player_owner_id`, `_ikona_id`) dla zgodnosci call-site'ow; wektory potwierdzaja brak wplywu.
8. Python w weryfikatorze ma Unicode 14.0.0 (starszy niz Node 16.0 / Rust): hash BMP w Pythonie rozni sie, wiec weryfikator porownuje znak po znaku tabele silnika z NFD Pythona (0 rozbieznosci wartosci, 0 kluczy po jednej stronie) - rownosc z wynikiem Node dla BMP zapewnia test Rust (`bmpHash`). To jawne ograniczenie niezaleznosci weryfikatora dla pelnego BMP.
